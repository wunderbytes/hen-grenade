## Protocol

1. Pi 400, mains power, wired display, nothing else running, desktop at the resolution under test.
2. Launch the **exported** arm32 binary (never a debug build or the editor):
   `./HenGrenade.arm32 --rendering-driver opengl3`
3. Enter the stress scene (F2). Vsync **off** (press V). 60-second run.
4. Record average / p99 frame time and draw calls from the on-screen metrics overlay.
5. Repeat at 720p, 1080p, and 4K output (cycle with R).
6. Repeat with vsync **on** to confirm a stable, hitch-free 60 over 60 s.
7. Record CPU temperature at start and end (`vcgencmd measure_temp`).

## Decision point

- **If 720p vsync-off p99 frame time ≤ 16.6 ms AND draw calls ≤ 20** → M0 passes.
  Proceed to M1.
- **If the frame criterion fails** → bisect with the stress scene toggles
  (particles / explosions / HUD) first. If a single feature dominates, tighten
  the budget. If the baseline itself is too slow, that is the ADR 0001 trigger:
  switch to LÖVE before writing any gameplay.

**M0 verdict: PASS** — reported 2026-09-12 from a run of the exported arm32 build
on the reference Pi 400: the stress scene ran correctly with no frame-rate
problem observed, and the Windows build runs. ADR 0001 is **not** triggered;
Godot stays. The numeric tables above still need transcribing so that M1 onward
has a baseline to regress against.
