## Implemented

1. **`GameMode`** (`src/sim/game_mode.gd`) — identity, round length, crate scale, crate-cap override, Hen speed, scoring rule. Two resources: `data/balance/modes/deathmatch.tres` (inherit everything, `KILLS`) and `hen.tres` (18000 ticks, scale 500, cap 250, speed 8, `HEN_TICKS`). `fingerprint()` mixes every field except `display_name` and `match_rules_path`.
2. **`Session`** (`src/app/session.gd`) — a static, not an autoload. The lobby writes `mode_id`, `MatchScene` reads it, tests set it. Quitting to the lobby keeps the last choice. Deathmatch is the default.
3. **`MatchRules` for Hen** (`data/balance/match_hen.tres`) — first to 1, `max_rounds` 1, same 240-tick scoreboard. Deathmatch `match.tres` is unchanged.
4. **Hen rules in the sim.** Token placement is one `next_index` after generation, Hen-mode only. Collection after movement. Drop on death is an ordered search and spends no draws. The token is not a pickup: blasts do not destroy it, kit scatter and crate regen treat its tile as occupied. The Hen cannot place, Toss, or Remote; Kick still works; speed is `hen_speed_units` and wins over FAST. Collecting re-arms leftover Remote bombs. `_tick_hen` sits after deaths and before respawns, so the death tick does not pay.
5. **Rule C.** Deathmatch `create()` spends the same number of PRNG draws as M3. There is a test that pins it against a probe RNG that only generates the arena.
6. **Lobby chips.** `DEATHMATCH` / `HEN GRENADE` under the title. LB/RB on any pad, `[` / `]` on the keyboard. Y/X/START/join/leave untouched. No D-pad, no Back, no Y.
7. **Views.** The Hen is a larger oval plus a three-point comb, drawn in one pass after the hunter rects so slot colour stays on the outline. The token is a gold disc with a chevron, drawn under flames, not in the power-up legend. HUD cards lead with hen-seconds; the clock Label reads `HEN P2` or `TOKEN`. Scoreboard title `HEN GRENADE  seed …`, rows `P1   94s   3k / 5d`.
8. **`golden_03`.** A committed hen-mode round that collects the token, dies as the Hen, and collects it again (5 collects, 4 drops in the recorded log). `golden_01` / `golden_02` state fingerprints and traces are identical to M3; only the rules `u32` moved, because `GameMode` joined the mix.

## Decisions taken during M3.5

All four borderline calls in the brief were implemented as written:

- One 5:00 round, not a best-of-3 of five-minute rounds.
- The token is match state, not a `Powerup.Kind`.
- No hit-point system.
- Deathmatch `create()` draws nothing extra for a token that is not there.

Tick order: `_tick_hen` was **inserted** after deaths and before respawns. `_tick_curses` was **not** moved to match the brief's illustrative list — moving it would have changed deathmatch. The deathmatch goldens staying put is the proof.

Fingerprint mix: `hen_ticks`, `hen_slot` and `hen_token_tile` are mixed only when they are not the deathmatch sentinels (0 / −1 / (−1,−1)). Mixing the zeros would have moved every M3 state hash without changing any rule. A hen round always has a token or a holder, so it still fingerprints.

Replay playback stores **effective** crate density in the header. `Replay.fresh_state` forces `crate_scale_permille = 1000` so create() does not scale an already-scaled number.
